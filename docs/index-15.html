Ce qui est testé, et où lire le code

Les sept feuilles CSS du jeu sont chargées sans modification. Les sprites sont dessinés dans des canvas 500 × 500 comme dans createEntity.js ; leur taille affichée est imposée par monstre.css, notamment height: 120px pour la mouche et width: 220px; height: 140px pour l’escargot. Aucun contour n’est calculé.

Le bloc CSS « 3. PROPOSITION », le template unified-entity et calibrateUnified(), dans cette page, contiennent l’essai. Une lecture du style du sprite au montage suffit. Les calques sont ses voisins : ils restent hors de son clip-path. La tremblote reste sur le sprite uniquement ; les effets conservent leurs animations propres. Seule l’échelle globale est commune.

parent d’échelle             ← transform: scale(...) uniquement
└─ entitesContainer          ← facteur existant × 0,85
   └─ gabarit fixe          ← largeur / hauteur CSS, fixées à la création
      ├─ orientation        ← miroir du dessin uniquement
      │  └─ sprite + canvas ← classe du monstre, clip-path, tremblote native
      ├─ aura-container     ← haut du gabarit
      ├─ effects-container  ← centre / haut selon la famille
      ├─ cast-container     ← bas du gabarit
      └─ messages           ← au-dessus, mêmes espacements pour tous

Les deux scènes utilisent les mêmes assets et les mêmes effets par colonne. Les messages et auréoles se répètent pour permettre l’observation ; il n’y a ni combat, ni sauvegarde, ni import du moteur. Les compteurs concernent le code de géométrie de ce prototype, pas le coût de rendu des GIF, filtres ou animations CSS. Désactiver « Mouvements CSS » remet les sprites au repos et fige les autres animations CSS ; les GIF continuent de jouer.

Les dimensions restent proportionnelles avec des plafonds de base : auréole et étourdissement 64 px de large ; mysticisme 140 × 200 px ; soin 110 × 160 px ; brûlure 110 × 140 px ; cercle au sol 190 px de large. L’écart de base de l’auréole est plafonné à 5 px. Les marges transparentes verticales du SVG sont recadrées par son affichage CSS. Tous ces plafonds suivent ensuite le scale du parent.

Les tailles et espacements proposés sont des réglages à juger ici. En vue d’ensemble, l’ancienne animation des dégâts, qui anime aussi la taille de police, est conservée des deux côtés afin d’isoler l’essai de placement. Le recalibrage n’a lieu qu’à la création ou au remplacement d’une entité.

En mode « Messages / dégâts », chaque famille a trois piles proches : centre, gauche, droite. Le centre est privilégié ; s’il a reçu un événement depuis moins de 240 ms, les suivants alternent gauche/droite. Chaque pile garde son dernier popup et au plus une sortie brève. Le bloc z-index 1 conserve les archives centrales : huit dégâts reçus dans la zone dégâts, six noms d’effets dans la zone effets. Lignes de 14 px, apparition en bas, remontée et disparition en 2,2 secondes. Les GIF n’ont aucune archive.

Essai inspiré du texte de combat de WoW : chiffres à empattements, contour sombre net, impact rapide puis montée régulière à taille lisible. Les critiques ont un rebond supplémentaire. Le texte reste opaque pendant 72 % de sa durée, puis se fond en continuant de monter. Durées : 1,25 seconde pour un dégât normal, 1,55 seconde pour un critique, 1,7 seconde pour une exécution critique. Les archives restent discrètes derrière le dernier impact. Les neuf piles et les deux archives sont en position absolue ; seuls les contenus s’animent. Les GIF gardent leur animation d’une seconde. Un critique remplace le picto de nature par le picto critique ; une exécution critique utilise son picto spécifique. Le montant garde la couleur de sa nature, les « !!! » prennent la couleur du critique (orange, rouge pour l’exécution critique). Tailles de base : normal 24 px, critique 32 px, exécution critique 40 px. Les noms d’effets incluent leur picto et leur valeur disponible, par exemple « Stun 3 scd ! ». Les durées sont converties en secondes, avec au plus une décimale. Vider le champ de durée permet d’essayer un effet sans durée connue.

Le nouveau flux anime uniquement transform et opacity. Un seul timer génère les événements de démonstration ; les fins d’animations retirent les messages. Quitter le mode, remplacer une entité, vider ou masquer l’onglet nettoie/suspend le travail concerné. Le témoin conserve ses animations actuelles et se limite à 48 messages par entité pour protéger l’onglet. Ce laboratoire ne modifie ni les sauvegardes ni le combat.
